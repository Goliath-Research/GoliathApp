# Schema apply

PostgreSQL schema changes ship as ordered SQL files under `workflow_engine/sql_pg/`. [`apply_schema.sh`](https://github.com/Goliath-Research/GoliathApp/blob/main/workflow_engine/sql_pg/apply_schema.sh) applies that list every time it runs. The files are written so the same ordered run can be repeated on a database that already has the objects: `CREATE … IF NOT EXISTS`, `CREATE OR REPLACE`, and `DROP FUNCTION IF EXISTS` / `DROP VIEW IF EXISTS` before a return row type changes. `CREATE OR REPLACE` cannot change a `RETURNS TABLE` row type (SQLSTATE 42P13) or replace a function with a narrower definition. Each function is defined in one place in the list. A later file drops the earlier overload when it widens an argument list.

An application that ships this engine applies the list once per release, to the existing database. The shell script has no release-version table and no skip-if-applied marker. One invocation applies every file in `SCRIPTS`.

## What the script runs

`apply_schema.sh` requires `psql` (PostgreSQL 15+; 17+ is what `00_schema.sql` recommends for SQL/JSON). Set standard libpq variables before running:

| Variable | Role |
|----------|------|
| `PGHOST` | Database host (required) |
| `PGPORT` | Port (default `5432`) |
| `PGDATABASE` | Database name (required) |
| `PGUSER` | Role name (required) |
| `PGPASSWORD` or `PGPASSFILE` | Authentication |
| `PGSSLMODE` | TLS mode (default `prefer`) |

The script checks `current_user` and `version()`, applies each file with `psql -q -v ON_ERROR_STOP=1 -f`, then runs `workflow_engine/contract/validate_contract.py` when `python3` or `.venv/bin/python` is available. It does not set `check_function_bodies`.

GoliathApp apply creates the portal navigation shell (`portal_shell_schema.sql`), organization tenancy (`portal_organization_schema.sql`), and `cfg.analyte` (`cfg_analyte_schema.sql`). Clinical portal tables (`portal."Customers"`, `portal."Samples"`, and related Omics domain DDL) are owned by descendant apps such as GoliathOmics and are not referenced from this tree.

## PL/pgSQL name clashes

`RETURNS TABLE` columns are variables. An unqualified column of the same name fails at call time with SQLSTATE 42702. Functions in this tree put `#variable_conflict use_column` as the first line of the body when that clash would happen. `workflow_engine/tests/test_pg_plpgsql_variable_conflict.py` fails the build if a new function reintroduces it.
